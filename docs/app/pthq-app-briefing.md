Method: inventory pass, then 4 grouped module readers, 2 auditors and 1 adversarial fact-checker over 20 website-grade claims, each citing `path:line` evidence. **How to use:** search the module tables for the feature; the `status` word is the answer. Only a `website_claim` sentence is safe to publish. The `caveat` is what must not be said.

**Status words:** `live` = wired end to end and reachable from navigation · `partial` = works with a named gap · `gated` = needs an env key or per-business configuration (named) · `hidden` = code exists, no UI exposes it · `parked` = documented as deferred, not built · `removed` = gone at HEAD.

## 1. Executive summary

- The app is a browser-based admin for painting businesses plus mobile-web screens for crew, on Expo web + FastAPI + MongoDB. **No native app, no offline mode, no push notifications.** It installs as a PWA.
- **Strong and real:** estimate builder with a rate library; public quote link with optional extras, draw-or-type e-signature and decline; quote and invoice PDFs; deposit invoice auto-drafted on acceptance; project created on acceptance; variations with public approve/decline; before/after photos, markup editor and a client completion report with public link and PDF; GPS clock-in/out; timesheets with approvals, lock and payroll CSV; crew daily reports; employee onboarding by QR; contracts e-signed by crew and countersigned; training library; performance ratings; equipment register; CRM with multi-contact clients, leads, duplicate merge, templates, automations; calendar with Google/Outlook/Apple read-only overlays and an ICS feed; Google Drive / OneDrive storage option; Lucy, the AI assistant, on the app's own Anthropic key with a per-business daily allowance and an audit log; team admins with access switches; sessions and device sign-out.
- **Gated on platform keys (work only when the owner has set them in the deployed env):** every email (Resend), AI features (Anthropic key), Google and Microsoft OAuth integrations, built-in GCS storage, Stripe billing. **Gated on the customer's own account:** SMS (their Twilio), Apple calendar (their app password), IMAP inbox.
- **Not real, despite the old marketing page:** AI estimating from photos or plans, AI photo validation, offline sync, native app, client card payment (removed 4 Oct, bank transfer only), client-facing daily reports, drag-and-drop Kanban, two-way calendar sync, Xero/MYOB, "trained on thousands of jobs", every testimonial and statistic.
- **Launch posture today:** sign-up is invite-gated (`TESTER_INVITES_REQUIRED=1`), legal docs are lawyer-review drafts with placeholders, transactional email still uses the `resend.dev` test sender, Stripe has never been browser-verified, and production needs a second `worker` process that `DEPLOY.md` does not mention.

## 3. Bugs and risks found on the way (for the app, not the website)

Security and privacy first:

1. `backend/services/passwords.py:155-158` **logs the stored password hash at INFO on every login.** Remove.
2. `POST /api/signup-leads`, `POST /api/employees/register`, `POST /api/telemetry/frontend-error`, `GET /api/public/report/{token}` have **no rate limit**. The lead form will be a spam target the day the website goes live.
3. `GET /api/mcp/health` is unauthenticated and lists tool names; `GET /api/merge-tags` has no auth. Low risk, but tidy before launch.
4. Twilio auth token (`sms.py:35`) and IMAP mailbox password (`comms.py:294`) are stored **in plain text** per tenant.
5. Google Drive photo uploads are set to **"anyone with the link"** so the app can render them (`google_drive.py:263-268`). Say so in the privacy policy or change it.
6. `memory/.tok` and `backend/tests/_creds.py` are tracked in a **public** repo and not git-ignored. Check and rotate.
7. Built-in GCS default bucket name is the legacy `josh-sano-employee-docs` (`gcs_utils.py`).
8. Router-level `require_*` dependencies only reject team members; anonymous requests pass through to the handler. Per-handler `Depends` is the only real auth boundary. The audit found no unprotected admin handler, but this is a footgun for new routes.

Functional:

9. Estimate builder ⋯ menu **"Convert to live project" always fails**: it posts to `/estimates/{id}/convert-to-project` (no such route) and routes to `/admin/live-projects` (deleted in Round 64). The list-drawer path works (`Builder.tsx:62,79`).
10. Crew **cannot cancel an equipment request**: the app calls `DELETE /equipment/requests/{id}` but the API only has `POST …/cancel`; the error is swallowed (`request-equipment.tsx:94,103`).
11. **Sign-in/out reminders fire at UTC 08:00 / 16:00**, so an Australian crew gets the morning reminder in the evening (`worker.py:59-60`; Round 63 flag 3). The employee query behind it is not tenant-scoped (`server.py:291`).
12. Claude writes a daily brief nobody sees (tokens burned daily per tenant; `dashboard_home.py:270-318`).
13. Default SMS body still says "Pay or view here" (`sms.py:207`) and the list-drawer reminder says "payment options" (`invoices.tsx:128`) although online payment was removed. The invoice-reminder automation template promises "pay online" (`automations.py:24`).
14. Crew-visible job files are flagged on the backend but the crew job screen never renders attachments (`ProjectPhotos.tsx`).
15. Crew "strike system" screen links to `/employee/training-videos`, which does not exist (`strike-system.tsx:35`).
16. Stale copy: Lucy gear "Text polish" switch, Help guides (`HelpGuides.tsx:59`), `GET /connected-services` still says Drive is "coming soon", `dashboard.py` docstring lists removed routes.
17. JWT lifetime is 2 h (`JWT_TOKEN_EXPIRE_HOURS`) with no refresh token; users re-login every two hours. `.env.example` documents `JWT_EXPIRES_MINUTES=1440`, which nothing reads.
18. Trial length: 90 days at sign-up vs 14 days in Stripe Checkout; `billing-success.tsx:52` and `FeatureGate.tsx:47` say "14-day". Standard annual is $470 in code, $468 on the old page.
19. Pricing-page feature lists do not match enforcement. Hard Pro gates: Equipment, Contracts, Training videos, Team admins, Performance, AI price refresh. Everything else (estimates, invoices, CRM, calendar, daily reports, Lucy chat) has no tier gate, and the frontend hard-codes everyone as Pro (`subscriptionContext.tsx:177-182`).
20. `frontend/app.json` still carries the legacy identity: name "For Painters", scheme `jscrew`, bundle id `com.sanopaint.crew`.
21. Josh Sano Painting & Decorating is baked into crew onboarding and team-events copy, the CRM signature placeholder, `ai_tools.py:2` and `invoice_payments.py:113`.
22. Production needs `python worker.py` beside uvicorn (11 scheduled jobs + the AI jobs poller). `DEPLOY.md` does not mention it (Round 63 report).

### What the checker found, claim by claim

**1. Clients can open a quote from a public link in their browser, choose optional extras, and accept it with an electronic signature (drawn or typed) without creating an account.**  
Fully wired end to end. /quote/[token] fetches GET /api/public/estimate/{token} with no auth, renders ClientDoc with selectable optional rows (onToggleOption), and an Accept dialog with Draw (canvas) / Type (rendered to PNG) signature modes that POSTs to /api/public/estimate/{token}/accept with signer_name, signature_data_url and accepted_options. The backend validates the PNG, stores signer/IP/time, applies the chosen options to totals and sets status accepted. Nothing in Rounds 50-64 removed or gated it.  
Evidence: `backend/routes/estimate_send.py:383`; `backend/routes/estimate_send.py:493`; `backend/routes/estimate_send.py:513`; `frontend/app/quote/[token].tsx:46`; `frontend/app/quote/[token].tsx:56`; `frontend/app/quote/[token].tsx:68`

**2. Quotes and invoices are generated as PDF documents (WeasyPrint) that the client can download from the public link and the admin can download or print.**  
services/pdf.py imports weasyprint and renders via HTML(string=doc).write_pdf(); routes/pdf.py exposes /estimates/{id}/pdf, /invoices/{id}/pdf, /public/estimate/{token}/pdf and /public/invoice/{token}/pdf. Both public pages have Download PDF and Print buttons. Admin side has Download PDF in the estimates drawer, the invoices drawer and the estimate builder's ... menu (opens the blob in a new tab). There is no dedicated admin Print button; printing is only via the browser on the opened PDF, but download is supported so the 'or' holds.  
Evidence: `backend/services/pdf.py:32`; `backend/services/pdf.py:251`; `backend/routes/pdf.py:149`; `backend/routes/pdf.py:195`; `frontend/app/quote/[token].tsx:52`; `frontend/app/admin/estimates.tsx:227`

Round 61b (4 Oct) removed the Pay now button, sticky bar and checkout call from /invoice/[token]; the page comment now reads 'bank transfer only - no Pay now, no bar, no checkout' and it only offers Download PDF / Print. The backend POST /public/invoice/{token}/checkout and the Stripe webhook still exist but have no frontend caller (the only checkout caller left is the subscription billing page). Invoice documents now show a Bank transfer card only.

It never emails or notifies; the admin sees a grey Unsent tag in Recent activity. Round 51, unchanged since.
