## 2. What exists today (from the code)

- Crew can read **nothing** of a job except `GET /projects/{id}/photos` (assigned jobs only: `items`, `photos_link`, `estimate_id`, and since Round 46 `attachments` = the "Crew can see" files). The crew photo screen (`app/employee/project/[id].tsx`, 19 lines) then calls `GET /estimates/{id}` — admin-only, 403 swallowed — so its title falls back to "Job photos". No employee route returns `crew_notes` today; nothing the owner marks "Visible to the crew" reaches a phone yet.
- **A job's `name` is normally not the client's name.** On the two main paths (admin Convert, client accept: `routes/projects.py:440–444`) `name` = the quote's job tag, else "street, suburb", else "Estimate {number}" ("Never the bare client name"), and `client_name` is stored beside it. On the third path (the admin sets a quote's status to accepted: `routes/estimates.py:328–385`, `_auto_create_project_from_estimate`) `name` = job tag, else the client's full name, else the customer's name, else the address, and **no `client_name` field is written**. The client's name is on `client_snapshot.name` on every path; the client's phone is `client_snapshot.phone` (the admin page's tel:/sms: buttons read it; the crew route never does).
- **Address:** at creation both `client_snapshot.address` and `location_address` are copied from the quote's `clientAddress`, not from its `jobAddressDetails` (`routes/projects.py:435, 482–484`). The admin page's "Edit location" writes `location_address` + the pin (`PATCH /projects/{id}/location`, declared at `:810`), but the admin page itself keeps displaying `client_snapshot.address` (`frontend/components/project/detail/JobSiteCard.tsx:23, 50, 68`), so an edited site address shows only as the moved pin. The crew route returns `location_address` when set, else `client_snapshot.address` (the site, not the client's postal address). (Admin-side quirk; flagged for Josh.)
- **Crew notes:** the builder's Quote details drawer saves `crew_notes` (one text) and `crew_visible` (one switch, "Visible to the crew"). The switch is persisted by the builder's PUT autosave; the drawer's PATCH drops it because `crew_visible` is not in the PATCH allow-list (`routes/estimates.py:417`). The project drawer's Notes tab writes a **list** shape (`[{id, text, crew_visible: false, …}]`) with no way to flip a note on. C2 reads both shapes. An empty string is "no note".
- **Scope:** on a migrated estimate the work is `areas[]` (`id, name, width, length, height, notes, order`) plus `lines[]` joined on `line.area_id` (`services/estimate_lines.py`). The existing helper **`flatten_estimate_lines(estimate, products)`** (`:295–317`, the one list behind Client view, the public page, the PDF and invoices) already returns one row per line in area order: `id, area_id, area_name, area_dims, area_note (only when the area's note is marked show-on-quote), name, sub ("prep · primer · 2 coats" for library lines, "repair", or the category), qty, unit, optional, chosen, photo_url, product {id, brand, name, pack, colour, surface} | null, hazard` plus money (`rate, total, line_total, unit_price`) and aliases. There is no `finish` field. Optional lines come back with `optional: true` and `chosen` (in `accepted_options`); the ones not chosen were not sold.
- **Paints and colours:** `project_materials` rows (`material_name, brand, size_label, colour, colour_code, quantity`; money fields `unit_cost, is_custom_price, line_cost, subtotal`). For a v2 quote these rows are **empty at creation** (`_copy_estimate_colours` reads only `estimate.materials` + `estimate.products`, never the lines' `product_id` / `colour`), so the route also derives products from `estimate.lines[]` where `product_id` is set (brand and name from `db.materials`, `pack` as the size, `colour`, the area names).
- **Crew:** `projects.assigned_employee_ids` (absent, not `[]`, until the owner first saves the crew); names from `employees.name`; role = `role`, else `role_label`, else "Painter" (⟨v3⟩ `position` is never written on an employee).
- **Variations:** `project.variations[]` `{id, title, description, price, timeframe, area, notes, lines [{name, category, unit, qty, rate, kind}], status, created_at, sent_at, responded_at, responded_by}`; `status` moves `draft → sent → approved | declined`.
- **Daily reports** (the crew form's picker lives in the shared `components/daily-report/AddReportModal.tsx:81`, for C4): `daily_reports` rows `{employee_id, project_id, submitted_at (naive UTC), hours_worked, tasks_completed (the whole WEATHER / TEAM / TASKS / CHECKLIST block), issues_notes, photos, admin_feedback, feedback_at, feedback_by, deleted_at}`; `parse_report(tasks_completed, issues_notes)['done']` gives the work lines; Replied = `admin_feedback` non-empty. **Crew-filed reports carry `project_id: null` today**: the crew form's job picker calls admin-only `GET /projects` (403 → empty list). So "My reports" on a job stays empty until C4 rewires the picker to the C2 list route.
- **Files:** `crew_rows(project_id)` → `[{id, name, kind (pdf | img | doc), size, open_url}]`, newest first, max 50; `open_url` is a 10-minute signed link.
- **Owner's first name:** the first word of `admin_settings.business_profile.owner_name` (what photo bylines use, `routes/project_photos.py:346`), else of `admins.owner_name`.
- **Statuses:** `quoted, in_progress, on_hold, done, invoiced`; dates `start_date, target_end_date, completed_date`.

## 5. Backend (the first crew routes of the crew app)

House convention for crew reads is `<resource>/mine` or `my-*` (`/employee-contracts/mine`, `/equipment/my-items`, `/daily-reports/my-reports`, `/timeclock/my-records`, `/validations/my`), so:

- **`GET /projects/mine`** — `current_employee: dict = Depends(get_current_employee)` (add `get_current_employee` to the `auth` import in `routes/projects.py`; the dependency carries `id, role, username, actor_name, jti, owner_admin_id`, no `name`); filter `{"owner_admin_id": current_employee["owner_admin_id"], "assigned_employee_ids": current_employee["id"]}` (the dependency already carries `owner_admin_id`; no second employee lookup). Returns `[{id, name, client_name, address, status, start_date, target_end_date, completed_date, updated_at, crew_count}]` (`client_name` and `address` derived exactly as in §3).
- **`GET /projects/mine/{project_id}`** — same filter plus `_id`; 404 otherwise. Returns **only**: `id, name, client_name, address, status, start_date, target_end_date, completed_date, owner_first_name, crew [{id, name, role}], site_contact {name, phone} | null, access_notes [{text, created_at}], areas [{id, name, dims, note, lines [{id, name, qty, unit, sub, product {brand, name, pack, colour} | null, photo_url}]}], added_work [{title, description, area, timeframe, approved_at, lines [{name, qty, unit}]}], materials [{name, brand, size_label, colour, colour_code, quantity, where, source: "job" | "quote"}], files [{id, name, kind, size, open_url}], my_reports [{id, date, hours_worked, work_lines, has_feedback}]` ⟨v3⟩ (no `location`, no `photos_link`: Directions uses the address and the photos section calls the photos route itself). Built field by field; the estimate and project documents are never passed through. `areas` = `flatten_estimate_lines(est, await products_map(db, current_employee["owner_admin_id"]))` (`from services.estimate_lines import flatten_estimate_lines, products_map`, `from database import db`; `est` read after `migrate_estimate` + `site_setup_on_read` as `GET /estimates/{id}` does) rows grouped by `area_id` in row order, rows with `optional and not chosen` dropped, each line copying only `id, name, qty, unit, sub, product {brand, name, pack, colour}, photo_url` — the dedupe for `materials` uses the row's `product.id` before that strip; `materials` = the `project_materials` rows (`source: "job"`, `where: null`, keyed by `material_id` + `colour`) plus each distinct line `product` not already covered by a job row (`source: "quote"`, `size_label` ← `pack`, `where` as in §3); `approved_at` = `responded_at`; `date` = `datetime.fromisoformat(submitted_at).replace(tzinfo=UTC).astimezone(await tz_for(owner_admin_id)).date().isoformat()`; `work_lines` = `parse_report(tasks_completed, issues_notes)['done']`; `has_feedback` = `bool(admin_feedback)`; `access_notes` = the string-shape note (`created_at: null`) and/or the list-shape notes with `crew_visible === true`; `site_contact` from a tenant-scoped `customers` read (`{"_id": customer_id, "owner_admin_id": …}`) after the assignment check, `null` when the job has no customer, the customer has no contacts, or none has `role == "site"`.
